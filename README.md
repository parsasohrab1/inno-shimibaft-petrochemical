## ۱. مقدمه

### ۱.۱. هدف
هدف این سند، تعریف دقیق و قابل سنجش نیازمندی‌های عملکردی و غیرعملکردی سامانه SPRO1 برای پیاده‌سازی در مجتمع پتروشیمی شیمی بافت (شامل واحدهای MTBE، MEK و واحدهای جانبی) است. این سامانه با بهره‌گیری از داده‌های تاریخی DCS/Historian و نتایج آزمایشگاهی، چهار ماژول تحلیلی هوشمند را یکپارچه می‌کند تا بهینه‌سازی شرایط عملیاتی، مدیریت مصرف انرژی و خوراک، پیش‌بینی کیفیت محصول و ارائه توصیه‌های عملیاتی بلادرنگ را ممکن سازد.

### ۱.۲. دامنه
سامانه SPRO1 شامل نرم‌افزار تحلیل داده، مدل‌های یادگیری ماشین و هوش مصنوعی، رابط کاربری وب و لایه‌های یکپارچه‌سازی با سیستم‌های موجود (DCS، Historian، LIMS) است. این سامانه **در فاز اول** برای واحدهای تولید MTBE و MEK در نظر گرفته شده و قابلیت توسعه به سایر واحدها را دارد. خروجی اصلی سامانه، **توصیه‌های عملیاتی قابل اجرا** برای اپراتورها و مدیران تولید است تا منجر به کاهش انحراف از مشخصات، کاهش شدت مصرف انرژی و افزایش راندمان تولید شود.

### ۱.۳. تعاریف و اصطلاحات
| اصطلاح | تعریف |
|---|---|
| **DCS** | سیستم کنترل توزیع‌شده (Distributed Control System) |
| **Historian** | پایگاه داده تاریخی ذخیره‌سازی متغیرهای فرآیندی |
| **LIMS** | سیستم مدیریت اطلاعات آزمایشگاهی |
| **Energy Intensity** | شدت مصرف انرژی (نسبت انرژی مصرفی به واحد تولید) |
| **OOS** | تولید خارج از مشخصات (Out-of-Specification) |
| **رافینیت ۱** | خوراک چهارکربنه ورودی به واحد MTBE |
| **رافینیت ۲** | محصول جانبی واحد MTBE |
| **MTBE** | متیل ترشیری بوتیل اتر (محصول اصلی) |

### ۱.۴. مراجع
1. نامه شماره 14050616001 مورخ 1405/06/16 شرکت پتروپاالتوس به پتروشیمی شیمی بافت.
2. IEEE Std 830-1998 و ISO/IEC/IEEE 29148:2018 (الگوهای SRS).
3. قانون جهش تولید دانش‌بنیان (مصوب 1401) و بند «ب» ماده ۱۱ (اعتبار مالیاتی تحقیق و توسعه).

## ۲. شرح کلی محصول

### ۲.۱. زمینه محصول
شرکت پتروشیمی شیمی بافت با ظرفیت اسمی ۹۰,۰۰۰ تن MTBE، ۵۰,۰۰۰ تن رافینت ۲ و ۵۰,۰۰۰ تن MEK، با چالش‌هایی مانند نوسان کیفیت خوراک (رافینیت ۱ و متانول)، تغییر شرایط عملیاتی و مدیریت مصرف انرژی مواجه است. رویکردهای سنتی مبتنی بر تحلیل دستی داده‌های تاریخی و نتایج آزمایشگاهی، امکان پیش‌بینی زودهنگام انحرافات کیفی و بهینه‌سازی همزمان انرژی و خوراک را محدود می‌کند. سامانه SPRO1 با تحلیل همزمان این متغیرها، خلأ مذکور را پر می‌کند.

### ۲.۲. کاربران اصلی
| کاربر | نقش در سامانه | نیاز اصلی |
|---|---|---|
| **اپراتور اتاق کنترل** | دریافت توصیه‌های بلادرنگ | هشدارهای واضح و قابل اجرا |
| **مهندس فرآیند** | تحلیل عملکرد و تنظیم حدود بهینه | دسترسی به مدل‌ها و سناریوسازی |
| **مدیر تولید** | پایش شاخص‌های کلان (بهره‌وری، انرژی) | داشبورد مدیریتی و گزارش‌های تحلیلی |
| **مهندس کیفیت** | پایش انطباق محصول با مشخصات | پیش‌بینی کیفیت و هشدار OOS |
| **مدیر انرژی** | پایش شدت مصرف انرژی | شناسایی نقاط پرمصرف و بهینه‌سازی |

### ۲.۳. محدودیت‌ها و مفروضات
- **مفروض:** داده‌های DCS/Historian با کیفیت قابل قبول (نرخ نمونه‌برداری حداقل ۱ دقیقه) در دسترس هستند.
- **مفروض:** نتایج آزمایشگاهی LIMS با تأخیر حداکثر ۲۴ ساعت در دسترس قرار می‌گیرند.
- **محدودیت:** سامانه SPRO1 جایگزین سیستم کنترل DCS نیست و توصیه‌های آن ماهیت **پیشنهادی** دارد؛ اعمال نهایی توسط اپراتور انجام می‌شود (Human-in-the-loop).
- **محدودیت:** فاز اول بر واحدهای MTBE و MEK متمرکز است.

- `PI-102` : فشار راکتور (بازه عملیاتی: ۰.۶۹–۱.۳۸ MPa)
- `FI-103` : دبی خوراک رافینیت ۱
- `FI-104` : دبی خوراک متانول
- `AI-105` : آنالیز آنلاین ایزوبوتن در خوراک (در صورت وجود)
- `TI-201` : دمای برج تقطیر جداسازی MTBE
- `FI-301` : دبی محصول MTBE
- `EI-401` : مصرف انرژی (بخار/برق) واحد

#### ۳.۲.۳. داده‌های واقعی قابل استفاده (از منابع عمومی)
با توجه به ماهیت محرمانه داده‌های فرآیندی پتروشیمی‌ها، استفاده از داده‌های واقعی صنعتی مشابه برای **توسعه و آزمون مدل‌ها** در فاز صفر پیشنهاد می‌شود:
- **مجموعه‌داده Gas Processing (IEEE DataPort):** شامل سری‌های زمانی چندمتغیره واقعی از واحدهای جداسازی فشار بالا، مبدل حرارتی و برج تثبیت‌کننده با پارامترهای دما، فشار، جریان و سطح است. این مجموعه برای توسعه الگوریتم‌های پیش‌بینی و تشخیص ناهنجاری قابل استفاده است.
- **مجموعه‌داده GIMSCOP/UFRGS:** شامل ۲.۵ روز داده واقعی حلقه‌های کنترل صنعت نفت و گاز (PV, SP, OP) که برای آزمون ماژول‌های تحلیل پایداری فرآیند مناسب است.
- **روش جانمایی:** در فاز پایلوت، داده‌های واقعی شیمی بافت با داده‌های مرجع فوق **نرمال‌سازی** شده و برای **پیش‌آموزش (Pre-training)** مدل‌ها استفاده می‌شوند؛ سپس مدل با داده‌های محلی **ریزتنظیم (Fine-tuning)** می‌شود.

#### ۳.۲.۴. تولید داده سنتتیک (Synthetic Data Generation)
برای سناریوهایی که داده واقعی کافی نیست (مانند شبیه‌سازی شرایط OOS یا کمبود خوراک)، از تولید داده سنتتیک با حفظ قیود فیزیکی و آماری استفاده می‌شود. کد پایتون زیر یک نمونه داده سنتتیک برای واحد MTBE تولید می‌کند:

```python
import numpy as np
import pandas as pd
from datetime import datetime, timedelta

def generate_mtbe_synthetic_data(n_points=10000, freq_min=1, seed=42):
    """
    تولید داده سنتتیک برای واحد MTBE با حفظ روابط فیزیکی پایه.
    پارامترها:
        n_points: تعداد نقاط زمانی
        freq_min: فاصله زمانی به دقیقه
        seed: دانه تصادفی برای تکرارپذیری
    خروجی:
        DataFrame با ستون‌های دما، فشار، دبی خوراک، خلوص MTBE و انرژی
    """
    np.random.seed(seed)
    time_index = [datetime(2025, 1, 1) + timedelta(minutes=i*freq_min) for i in range(n_points)]
    
    # شبیه‌سازی نویز پایه و روند
    t = np.linspace(0, 10, n_points)
    
    # دمای راکتور (بازه 74-77 درجه سانتی‌گراد با نوسان کنترل‌شده)
    temp_reactor = 75.5 + 1.2 * np.sin(0.1 * t) + np.random.normal(0, 0.3, n_points)
    temp_reactor = np.clip(temp_reactor, 74.0, 77.0)
    
    # فشار راکتور (بازه 0.69-1.38 MPa)
    pressure = 1.0 + 0.15 * np.sin(0.05 * t) + np.random.normal(0, 0.05, n_points)
    pressure = np.clip(pressure, 0.69, 1.38)
    
    # دبی خوراک رافینیت 1 (kg/h) - با نوسان و روند کاهشی جزئی
    feed_flow = 10000 - 2 * t + 200 * np.sin(0.2 * t) + np.random.normal(0, 100, n_points)
    feed_flow = np.maximum(feed_flow, 3000)
    
    # نسبت متانول به ایزوبوتن (مولار) - بهینه حدود 1.1
    meoh_ratio = 1.1 + 0.05 * np.sin(0.15 * t) + np.random.normal(0, 0.02, n_points)
    
    # خلوص MTBE (تابع دما و نسبت خوراک) با نویز
    purity = 98.5 - 0.3 * np.abs(temp_reactor - 75.5) - 2.0 * np.abs(meoh_ratio - 1.1) + np.random.normal(0, 0.2, n_points)
    purity = np.clip(purity, 95.0, 99.5)
    
    # Energy Intensity (GJ/ton) - با افزایش دما و کاهش خلوص افزایش می‌یابد
    energy_intensity = 8.0 + 0.5 * np.abs(temp_reactor - 75.5) + 0.3 * (99.0 - purity) + np.random.normal(0, 0.1, n_points)
    
    df = pd.DataFrame({
        'timestamp': time_index,
        'reactor_temp_C': temp_reactor,
        'reactor_pressure_MPa': pressure,
        'feed_flow_kg_h': feed_flow,
        'meoh_isobutene_ratio': meoh_ratio,
        'mtbe_purity_pct': purity,
        'energy_intensity_GJ_t': energy_intensity
    })
    return df

# نمونه تولید و ذخیره
synthetic_df = generate_mtbe_synthetic_data(n_points=5000)
print(synthetic_df.head())
```

| **SI-02** | API RESTful برای تبادل داده با LIMS و سیستم برنامه‌ریزی تولید. |
| **SI-03** | خروجی گزارش‌ها در قالب‌های PDF، Excel و CSV. |

### ۳.۴. نیازمندی‌های غیرعملکردی (Non-Functional Requirements)

| شناسه | دسته | نیازمندی | معیار سنجش |
|---|---|---|---|
| **NFR-01** | عملکرد | زمان پاسخ برای توصیه‌های بلادرنگ ≤ ۳ ثانیه | آزمون بار با ۵۰ کاربر همزمان. |
| **NFR-02** | دسترس‌پذیری | در دسترس بودن سامانه ≥ ۹۹.۵٪ در ساعات عملیاتی | محاسبه ماهانه. |
| **NFR-03** | امنیت | احراز هویت مبتنی بر نقش (RBAC) و رمزنگاری داده‌ها در حال انتقال (TLS 1.3) | ممیزی امنیتی سالانه. |
| **NFR-04** | قابلیت نگهداری | مستندسازی کامل مدل‌ها (Model Card) و امکان بازآموزی دوره‌ای | بازآموزی خودکار ماهانه یا بر اساس انحراف عملکرد. |
| **NFR-05** | مقیاس‌پذیری | پشتیبانی از حداقل ۵,۰۰۰ تگ داده و ۱۰ سال داده تاریخی | آزمون ذخیره‌سازی و بازیابی. |
| **NFR-06** | قابلیت ردیابی | ثبت کلیه توصیه‌ها، هشدارها و اقدامات اپراتور با مهر زمانی | لاگ کامل و غیرقابل تغییر. |

### ۳.۵. نیازمندی‌های هوش مصنوعی و یادگیری ماشین (AI/ML)

| شناسه | نیازمندی |
|---|---|
| **AI-01** | مدل‌ها باید با داده‌های محلی شیمی بافت **ریزتنظیم** شوند و عملکرد آن‌ها به صورت دوره‌ای پایش گردد. |
| **AI-02** | هر مدل باید دارای **کارت مدل** شامل نوع الگوریتم، داده آموزش، معیارهای عملکرد و محدودیت‌ها باشد. |
| **AI-03** | سامانه باید قابلیت **یادگیری فعال (Active Learning)** داشته باشد تا با بازخورد اپراتور، دقت پیش‌بینی بهبود یابد. |
| **AI-04** | توصیه‌های مدل باید **قابل تفسیر** باشند (حداقل رتبه‌بندی اهمیت ویژگی‌ها با SHAP یا روش مشابه). |
| **AI-05** | در صورت کاهش عملکرد مدل (به عنوان مثال، افزایش خطای پیش‌بینی بیش از ۱۰٪)، سامانه باید هشدار **نیاز به بازآموزی** صادر کند. |

### ۳.۶. نیازمندی‌های انطباق و اعتبار مالیاتی
سامانه SPRO1 به گونه‌ای طراحی شده که کلیه الزامات **طرح تحقیق و توسعه** موضوع بند «ب» ماده ۱۱ قانون جهش تولید دانش‌بنیان را احراز کند تا هزینه‌های پیاده‌سازی آن از محل **اعتبار مالیاتی** قابل کسر باشد. مستندات زیر باید تولید و نگهداری شوند:
- شرح نظام‌مند طرح (شامل اهداف، روش‌شناسی و نوآوری).
- مستندات هزینه‌های تحقیق و توسعه (نیروی انسانی، تجهیزات، مواد و آزمون‌ها).
- گزارش خروجی‌های فناورانه (بهبود فرآیند، محصول جدید یا ارتقای کیفیت).
